## 4) Core demo steps to narrate

### Feature 1: Document ingestion
User goal:
- Get a new matter ready quickly without manual document triage.

User feeling:
- Starts rushed and uncertain.
- Should move toward clear and in-control once readiness is visible.

What to show:
- Matter open state.
- Document ingestion/readiness status.
- Run start when ready.

Caveat to mention:
- Current runtime is optimized for deterministic trust flows; ingestion geometry maturity is still evolving.

### Feature 2: Citation viewer and trust loop
User goal:
- Verify that the answer is grounded in source documents.

User feeling:
- Moves from skepticism to confidence when they can click and verify.

What to show:
- Open a report row.
- Click a citation chip.
- Show highlight/source context in viewer.

Caveat to mention:
- Trust posture is fail-closed: if evidence cannot be verified, it is surfaced explicitly rather than hidden.

### Feature 3: Chat with matter docs
User goal:
- Ask follow-up questions with context from the current matter/run.

User feeling:
- Gains speed without losing context integrity.

What to show:
- Chat in matter context.
- Run-scoped behavior and source-linked answers.

Caveat to mention:
- Chat scope is intentionally constrained for trust and clarity over open-ended flexibility.

## 5) Post-demo technical architecture: what was used and why

### App and UI
- Next.js App Router + React + Tailwind.
- Why: fast iteration, strong server/client boundaries, and practical UI speed for a PoC.

### Orchestration
- Workflow DevKit (WDK) step-based execution.
- Why: durable, retryable, observable workflow boundaries instead of ad hoc async flows.

### Data and state
- Postgres as system-of-record for runs, rows, citations, and workflow state.
- Why: single source of truth, easy querying, auditable state transitions.

### Document/object storage
- Local object storage path for PoC asset handling.
- Why: simple, low-friction setup for development and demo reliability.

### Evidence and trust model
- Citation-linked evidence flow and explicit status outcomes (`needs_review`, `missing_input`, `citation_failed`).
- Why: trust should be inspectable, not implied by fluent text.

### LLM layer
- AI SDK/gateway-style model integration and routing.
- Why: portable model plumbing, easy model/provider swaps, and consistent call patterns.

### Retrieval and grounding
- Retrieval + chunk-based grounding flow with citation locking posture.
- Why: answers must be tied to concrete evidence units, not free-form generation alone.

### Validation and safety
- Zod boundary validation and fail-closed behavior on integrity breaks.
- Why: predictable contracts, safer error handling, and explicit operator feedback.

### Demo posture
- Synthetic datasets, explicit caveats, and journey-led UX checks.
- Why: gives deterministic demos while still stress-testing user trust moments.

## 6) Trade-offs to say out loud
- Prioritized trust and defensibility over broad feature surface.
- Prioritized explicit states and reviewability over magical UX.
- Prioritized reliability and observability over premature complexity.
