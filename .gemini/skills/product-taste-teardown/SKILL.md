# Product Taste Teardown

## When to use
Trigger this skill when asked to:
- Tear down a flow (onboarding, dashboard, docs, homepage) and propose improvements
- Raise the quality bar with crisp principles and trade-offs
- Reduce confusion, anxiety, or drop-offs

## Inputs to collect
- Target user + job.
- Flow description, screenshots, or copy.
- Evidence (drop-off points, complaints, support tickets, session notes).

## Workflow
1) Define job and success
   - State what “done” looks like.
   - Simulate user feelings at each step.

2) Run the teardown
   - Walk the experience step-by-step.
   - Log expectation gaps and friction.
   - Note where trust is demanded without being earned.

3) Apply WAYRTTD
   - Use references/taste-wayrttd.md to:
     - Describe current structure
     - Identify real problems
     - Propose optimisations
     - Prioritise changes

4) Solve with principles
   - Draft 5–7 proposed principles.
   - Debate, cut, and stack-rank.
   - Generate option Z if stuck in X vs Y.

5) Produce recommendations
   - Group into quick wins, medium lifts, big bets.
   - Validate comms clarity using references/compelling-comms.md.

## Output artefacts
- Teardown report (assets/teardown-template.md)
- Principle stack and chosen option
- Prioritised change list

## Bundled resources
